Play Console нужно обновить вместе с кодом, иначе форма станет ложной
декларацией — это само по себе основание для снятия приложения.

## 2. Разрешения приложения и зачем каждое

Из [`AndroidManifest.xml`](file:///Users/roman.struchev/git/vpn/vpn/android/app/src/main/AndroidManifest.xml) — пригодится для секции разрешений в листинге и для ответа ревьюеру, если он спросит:

| Разрешение | Зачем |
|---|---|
| `INTERNET`, `ACCESS_NETWORK_STATE` | Собственно работа VPN-клиента и REST-запросы к API. |
| `BIND_VPN_SERVICE` (через `<service>` intent-filter `android.net.VpnService`) | Ядро функциональности — поднятие туннеля через `VpnService`. |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SPECIAL_USE` | VPN-туннель обязан работать как foreground-сервис, чтобы Android не убивал соединение в фоне. |
| `POST_NOTIFICATIONS` | Показ статуса подключения в уведомлении (API 33+). |

Никаких разрешений на контакты, SMS, местоположение, камеру, микрофон, хранилище — их нет в манифесте и не должно появляться без пересмотра этого документа.

## 3. Черновик политики конфиденциальности

Публиковать по стабильному публичному URL (например, `https://<домен>/privacy`) и указать в:
Play Console → Листинг → Privacy Policy, и в Data safety форме.

> ### Политика конфиденциальности NextGen VPN
>
> **Что мы собираем**
> - Email и хеш пароля — для аутентификации (либо Telegram ID при входе через Telegram Mini App на сайте/в боте — в самом Android-приложении вход только по email/паролю).
> - Баланс счёта и история пополнений — для биллинга.
> - Список ваших устройств (название, платформа) — для контроля лимита устройств по тарифу.
> - Агрегированные счётчики потребления трафика (байты за период) — для контроля квоты тарифа.
> - Обезличенная телеметрия подключения (страна/оператор, транспорт, факт неудачи подключения) — для диагностики блокировок и выбора резервных серверов. Она не содержит ни IP адресов назначения, ни посещённых доменов.
>
> **Чего мы не собираем и не храним**
> - Мы не ведём журнал посещённых вами сайтов, IP-адресов назначения или DNS-запросов внутри туннеля.
> - Мы не используем сторонние SDK аналитики, рекламы или трекинга — в приложении их нет.
> - Мы не запрашиваем доступ к контактам, SMS, местоположению, камере или микрофону.
>
> **Как используются данные**
> Исключительно для работы сервиса: аутентификация, биллинг, контроль лимитов тарифа, выбор рабочего сервера. Данные не продаются и не передаются третьим лицам для маркетинга.
>
> **Хранение и защита**
> Пароль хранится в виде хеша. JWT-токен на устройстве хранится в зашифрованном виде (Android Keystore через EncryptedSharedPreferences). Данные хранятся на серверах сервиса; актуальный регион размещения указывается отдельно при запуске.
>
> **Удаление данных**
> Запрос на удаление аккаунта и связанных данных направляется через [контактный канал — заполнить перед публикацией]. Баланс счёта невозвратен (см. условия использования) — это единственное исключение из полного удаления.
>
> **Изменения политики**
> При существенном изменении состава собираемых данных документ обновляется, а пользователи уведомляются в приложении.
>
> Последнее обновление: [дата публикации].

**Перед публикацией: заполнить квадратные скобки** (контактный канал, регион серверов, дата) — сейчас в них плейсхолдеры, а не реальные значения.

## 4. Data Safety — маппинг по полям формы Play Console

Google группирует вопросы по категориям данных. Ниже — что отвечать **для Android-приложения**, исходя из фактической модели данных (`server/.../entity/User.java`, `Device.java`, `Subscription.java`, `ConnTelemetry.java`) и того, что реально отправляет `android/app/src/main/java/com/vpn/android/api/ApiClient.java`.

| Категория данных | Собирается? | Передаётся с шифрованием? | Можно удалить? | Обязательна для работы? |
|---|:---:|:---:|:---:|:---:|
| Email-адрес | Да | Да (HTTPS) | По запросу | Да (аутентификация) |
| Идентификаторы пользователя (userId, referralCode) | Да | Да | По запросу | Да |
| Финансовая информация (баланс, история пополнений) | Да | Да | Нет (юридически значимая запись биллинга) | Да, если используется платный тариф |
| Информация об устройстве (название, платформа — вводится пользователем) | Да | Да | По запросу | Да (контроль лимита устройств) |
| Использование приложения (счётчики трафика, факты подключения/отключения) | Да, агрегированно | Да | По запросу | Да (контроль квоты) |
| Точное/приблизительное местоположение | **Нет** | — | — | — |
| Контакты, SMS, фото, файлы, календарь | **Нет** | — | — | — |
| Данные о посещённых сайтах / история браузера | **Нет — принципиально, архитектурный инвариант** | — | — | — |
| Рекламные идентификаторы | **Нет** | — | — | — |
| Данные передаются третьим сторонам | **Нет** | — | — | — |

Практический смысл последней строки: `android/app/build.gradle` не подключает ни одного стороннего SDK (аналитика, реклама, крэш-репортинг) — весь сетевой трафик приложения идёт только на собственный API-сервер (`BuildConfig.API_BASE_URL` + резервные домены, Фаза 10) и, после подключения VPN, через собственные ноды.
